“Needed” must not quietly mean “mandatory.”

A skill can improve an agent workflow without being a prerequisite for the underlying CLI command. If a particular assisted mode truly cannot work without it, explain that requirement and provide an exit to the non-AI workflow. Required dependencies follow their existing installation contract.

THE STRATEGIC OPENING

Be better at relevance, not bigger at installation.

BORROW

Explicit setup + visible scope

AWS contributes the front door. Claude contributes review and readiness. Skills CLI contributes granular, project-aware installation.

DIFFERENTIATE

A task-aware invitation

azd knows the selected workflow and project. Use that context to explain a recommendation, not to infer broad installation consent.

05 / THE UX CONTRACT

Predictable by design.
Respectful by default.

Every entry point should make the same promises. The install invitation changes with the task; the rules do not.

01

Explain the value

Name the task benefit, source, publisher, and exact contents. Avoid vague claims like “required for Azure.”

02

Bound the change

One selected assistant. Project scope where supported. Explicit disclosure for user-wide or broader package changes.

03

Honor the answer

Skipping optional guidance preserves the original workflow. Consent is not inherited from a template or extension.

04

Prove readiness

Separate installed, discovered, loaded, authenticated, and permitted. Never promise that a skill repaired a deployment.

RECOMMENDATION MEMORY

Not now must mean something.

Proposed policy
SUPPRESSION KEYproject + assistant + purpose + capability set

Remember a decline for this context. A new CLI invocation, restart, or patch release is not a new reason to ask.

RESURFACE ONLY WHEN

The user explicitly returns to setup, requests a materially different assistance task, or reviews a changed recommendation that affects the needed capabilities. Explain the difference; never silently reset “not now.”

STATE & RECOVERY RULES

Design the less convenient moments.

Already installed, bundled, or supplied by another installer

Resolve usable guidance for the actual host, scope, and version. Recognized project-local skills count; do not download another copy merely to claim ownership. Record provenance without adopting or deleting externally managed files.

Try bundled guidance →
Multiple assistants or no supported assistant

Default to a known active host, visibly; otherwise ask. Detection is not permission to target every assistant. If no host exists, explain the prerequisite and let the user continue without skills. Installing a runtime or assistant needs separate consent.

Try a missing prerequisite →
Optional updates and custom content

Keep compatible installed guidance usable. Offer a reviewable update without silently replacing modified or user-authored files. A conflict is a stop-and-review state, not permission to back up and overwrite. Version pinning and host precedence need an engineering contract.

Try a custom-content conflict →
Offline, proxy, approved sources, and organization policy

Report the actual acquisition problem. Continue the non-AI workflow where possible. Offer approved-source instructions or an administrator path, not an automatic unapproved mirror. Policy denial is not a transient network error to retry around.

Try policy denial →
Partial installation and retry

Report per-item status and remaining work. Retry only failed items; do not repeat already successful installs. Avoid destructive rollback of shared assets. If an optional bundle fails, preserve the original command and explain which assisted capabilities are unavailable.

Try a partial install →
Installed but not ready in the current session

Ask the host what is active where supported. A new file on disk does not prove a running agent has loaded it. Provide host-specific reload guidance or a new-session handoff and preserve the original task. MCP configuration is not authentication or action approval.

Try the readiness handoff →
Shared skills, extension removal, and cleanup

Do not remove shared guidance when its companion extension is removed. Explicit removal names the assistant and scope and touches only installer-owned content. In-use detection, ownership records, and cross-installer identity are engineering questions; absence of telemetry is not proof that a skill is unused.

Try lifecycle management →
Non-interactive commands and coding agents

Return a machine-readable plan, missing capability identifiers, and actionable next steps. Optional guidance should not change the original command's exit status. Acquisition requires explicit preapproval with target, scope, and source; generic yes-to-all must not imply consent to unrelated installs.

Try automation →

KEEP THE CONCEPTS SEPARATE

Guidance is not permission.

Skill

Workflow instructions, sometimes with scripts or tool references. Review source and content; skill-only does not mean risk-free.

Plugin

A packaging boundary. May contain skills, MCP servers, hooks, and other components. Disclose the actual manifest.

MCP connection

Tool integration. Configuring it does not grant Azure permissions or approve future actions.

Extension / runtime

A CLI capability or executable dependency. Its installation has a separate requirement and consent model.

06 / DECISIONS & ROLLOUT

Ship the smallest
trustworthy system.

Start by making one relevant offer work well. Expand only when state, scope, and recovery behave consistently.

01
FIRST / FOUNDATIONAL CONTRACT

One contextual companion

Foundry extension completion: missing-state detection, selected assistant, explicit scope, skip, install receipt, and readiness. Keep the existing extension installation independent.

Exit criterion: users can explain what changed and continue after declining or a failed optional install.
02
NEXT / INTENTIONAL SETUP

A front door and a return path

Explicit assistant setup and management without an azd project. Use the same plan model, package boundaries, provenance, update, and removal behavior.

Exit criterion: setup is idempotent and never changes an unselected assistant or scope.
03
THEN / CONTEXTUAL EXPANSION

Projects and AI handoffs

Trusted project recommendations, bundled-skill recognition, assistance-gated setup, and requested troubleshooting. Apply suppression across all entry points.

Exit criterion: no repeated prompts, no downloads on ordinary init or failure alone, and no policy bypass.

DECISIONS FOR THE ROOM

Align on policy before polishing prompts.

01

What is the unit of installation?

Individual skills for narrow tasks; the existing full Azure plugin only when a user chooses broader tooling. Validate real catalog and host capabilities before promising selective plugin contents.

Recommend
02

Where does the setup destination live?

Evaluate azd tool as an orchestration surface against native host commands. Keep one recognizable management path and avoid a second package registry.

Validate naming
03

What does “project-local” mean?

Distinguish local files for this developer from committed recommendations for a team. Never silently commit setup or imply that a clone grants installation consent.

Host contract
04

When is a skill truly required?

Make recommended guidance optional by default. Document any specific assisted mode that cannot continue without it, and offer an explicit return to the non-AI workflow.

Product decision

VALIDATION PLAN

Measure useful adoption. Not install volume.

Formative tasks

Start without skills, install for one assistant, decline and repeat the task, join a project with bundled guidance, recover from a partial failure, and ask for deployment help.

Compare explicit-only, contextual-only, and hybrid entry points. Include new Azure users, experienced CLI users, and platform-managed teams.

Primary outcomes

  • Can users predict the target, scope, and contents before confirming?
  • Can they complete or resume their original task?
  • Do irrelevant offers and repeat prompts fall?
  • Does the installed guidance become usable in the intended host?

Guardrails & instrumentation

Track offer reason, plan acceptance, skipped reason when volunteered, per-item completion, readiness outcome, and task resumption with appropriate consent.

No transcript, project-code, or secret collection. Set numerical targets after a baseline; install rate alone is not a success metric.
