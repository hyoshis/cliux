azd extension install · redirect safety

Make the new source visible when trust changes.

An interactive CLI prototype for installing extension bundles from HTTPS URLs. Redirects stay quiet until the destination crosses a website boundary.

Design principle

Prompt when the source of the extension differs from the source the user explicitly chose.

Cross-website redirect

Show the original and final URL, explain the trust decision, and default to No.

Confirmation
>_ azd
PowerShell

PS C:\workspace> azd extension install https://short.example/contoso-tools.zip

Download redirects to a different website: https://downloads.example.net/contoso-tools.zip

? Trust the new destination and continue? (y/N)

Cross-website redirect in non-interactive mode

--no-prompt is not consent. Fail with a specific recovery path.

Error
>_ azd
CI

$ azd extension install https://short.example/contoso-tools.zip --no-prompt

ERROR: Extension redirects to a different website

https://downloads.example.net/contoso-tools.zip

To approve the redirect automatically, run again with --force.

Secure connection downgrade

Show the secure and insecure URLs, require confirmation, and default to No.

Confirmation
>_ azd
PowerShell

PS C:\workspace> azd extension install https://short.example/contoso-tools.zip

Download redirects to an insecure connection: http://downloads.example.net/contoso-tools.zip

? Continue with the insecure download? (y/N)

Explicit cross-website redirect approval

Automation can express the security decision separately from suppressing prompts.

Allowed
>_ azd
CI

$ azd extension install https://short.example/contoso-tools.zip --force

(!) WARNING: Download redirected to https://downloads.example.net/contoso-tools.zip

<continue the flow>

Redirect policy

The user experience follows the security boundary.

  1. 1
    Different hostname Show the destination and ask for confirmation. Default to No.
  2. 2
    HTTPS → HTTP Show the insecure destination in red and ask for confirmation. Default to No.
  3. 3
    --no-prompt Fail, show the destination, and explain how to approve with --force.
  4. 4
    --force Approve the redirect automatically, show a warning, and continue.
Supporting behavior

Show the redirect destination by default, and never forward credentials across a host boundary.
