A MODULE, NOT A SEPARATE SHELL05 / 11

This is the relationship I want to make clear. Windows PowerShell came first—it shipped in 2006 as Windows’ automation shell. Azure PowerShell came later and was built on top of it. Windows PowerShell is the foundation: a shell and scripting language. Azure PowerShell is not a separate program—it’s a set of modules, today called the Az module, that you install into PowerShell. Once it’s installed, PowerShell gains thousands of commands for Azure, like Get-AzResourceGroup or New-AzVM.

An analogy: PowerShell is the phone; the Az module is an app you install on it. Everything people already know about PowerShell—its syntax, pipeline, and scripts—carries over to Azure.

Nuance: it works in Windows PowerShell 5.1, but PowerShell 7 is recommended, and with PowerShell 7 it runs on macOS and Linux too.

RESOURCE MANAGEMENT / DIFFERENT CONVENTIONS06 / 11

I’ve worked on both. They manage the same Azure resources and can do most of the same tasks; the difference is who they’re built for.

Azure PowerShell lives inside PowerShell. It uses PowerShell’s verb-noun naming and returns objects, so it’s the natural choice for Windows administrators and IT pros who already have PowerShell scripts. PowerShell is object-oriented: each command hands real objects—with properties like name and location—to the next command, instead of plain text.

Is it true that Windows users prefer PowerShell? Often, yes—especially admins and IT pros who grew up with it. But it’s not universal: many Windows developers use az, especially when they share scripts with Mac or Linux teammates.

Azure CLI is its own program, the az command. It doesn’t depend on any particular shell—Bash on Linux or macOS, cmd on Windows, even inside PowerShell—and it returns JSON. That shell-neutral design is why it’s so common with cross-platform developers: Linux and macOS users, Docker containers, CI/CD pipelines like GitHub Actions, and many of the samples in Azure docs. It also has an extension model, so teams can ship new commands outside the core release.

Nuance worth stating precisely: Azure CLI is open source under the MIT license, and so are PowerShell 7 and azd. Azure PowerShell’s code is public on GitHub but uses Microsoft license terms. Azure PowerShell also runs on macOS and Linux with PowerShell 7, so Azure CLI’s edge is mostly that it fits the habits of the broader cross-platform developer community.

SHELLS HOST · CLI TOOLS RUN07 / 11

One distinction that helps everything click: a shell versus a CLI tool.

A shell is the environment you type commands into—PowerShell on Windows, Bash or zsh on Mac and Linux. PowerShell is a shell and a language. Azure PowerShell isn’t a separate shell; it adds Azure commands inside PowerShell, so they share PowerShell’s object pipeline.

Azure CLI (az) and Azure Developer CLI (azd) are CLI tools: standalone programs you launch from whatever shell you’re in. That’s why they behave the same in PowerShell, Bash, or cmd, and why they return text—usually JSON—rather than PowerShell objects.

RESOURCE OPERATIONS ↔ APP WORKFLOW08 / 11

Azure CLI, or az, is broadly focused on Azure resource operations. Azure Developer CLI, or azd, is focused on the application lifecycle: getting an application and its infrastructure ready for Azure, then deploying and iterating.

This is a difference in emphasis, not an absolute boundary. Azure CLI can deploy resources and applications too. A developer might use azd to provision and deploy an app, then use az for a particular resource-management task.

EXAMPLE COMMANDS / NOT A LIVE DEPLOYMENT09 / 11

A typical starting point is a template that contains application code, Azure configuration, and infrastructure as code. azd init -t hello-azd initializes an example template. azd up provisions the configured resources and deploys the app. After changing code, azd deploy can deploy the update.

You can also start from your own code instead of a template. This is a static illustration: running the commands requires the appropriate setup, sign-in, and an Azure subscription, and creating resources can incur charges. Infrastructure changes can be applied with azd provision or azd up.
